# Шаблон глоссария продукта

Скопируйте таблицу в глоссарий продукта. Один термин — одна строка. Универсальные правила остаются в `terminology.md`.

## Таблица

| Термин | Определение | Метка интерфейса | Имя в API | Запрещённые синонимы | Область | Владелец | Статус |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Пользователь | Человек, который работает с продуктом | **Пользователь** | `user` | юзер | Пользовательская документация | Документация | активный |
| Репозиторий | Место хранения кода и истории изменений | **Репозиторий** | `repository` | репа | Пользовательская и внутренняя | Разработка | активный |
| ... | ... | ... | ... | ... | ... | ... | ... |

## Как заполнять

1. Найдите термин в глоссарии, интерфейсе, API и существующей документации.
2. Проверьте, нет ли дубля или конфликта.
3. Запишите определение одним предложением.
4. Укажите метку интерфейса точно, с регистром и оформлением.
5. Укажите имя в API в моноширинном.
6. Перечислите запрещённые синонимы.
7. Укажите область: пользовательская документация, внутренняя документация или обе.
8. Назначьте владельца и статус.
9. Добавьте 1–2 примера в отдельный раздел глоссария.

## Статусы

- **активный** — используйте в новых текстах.
- **предложенный** — ждёт решения.
- **устаревший** — не используйте; оставьте ссылку на новый термин.

## Процесс обновления

1. Предложите изменение: термин, определение, причина.
2. Проверьте по интерфейсу, API и юридическим текстам.
3. Согласуйте с владельцем продукта и переводчиками.
4. Обновите документацию, интерфейс, API и переводы.
5. Термин, помеченный устаревшим, оставьте со ссылкой «см. также».
6. Обновите поисковый индекс и редиректы.
7. Сообщите команде.

## Проверка

- У каждого активного термина есть определение и владелец.
- У каждого термина есть метка интерфейса или имя в API, если они существуют.
- Запрещённые синонимы не используются в новых текстах.
- Устаревшие термины не исчезают без ссылки.
