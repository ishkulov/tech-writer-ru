# Термины и лексика

## Как пользоваться

Приоритет источников:

1. Глоссарий продукта.
2. Метка интерфейса в шагах.
3. Этот файл.

Если источники расходятся:

- в юридическом тексте — формулировка закона или договора;
- в шагах — метка интерфейса;
- в прозе — термин глоссария;
- в коде — идентификатор API без перевода;
- в цитате — формулировка источника.

Одно понятие — один термин. Не заменяйте термин синонимом для разнообразия и не используйте одно слово для разных сущностей.

Если термина нет в глоссарии, проверьте интерфейс и существующую документацию. Если и там нет, поставьте `{...}` и перечислите его в блоке «Что уточнить». Не угадывайте.

Регистры:

- **Пользовательская документация** — руководства, справочники, UI-тексты, примечания к выпуску, README для пользователей.
- **Внутренняя документация** — runbook, ADR, README для разработчиков, внутренние справочники API.
- **Внутренняя переписка** — чат, тикеты, комментарии в коде и PR.

## Не путать

| Термин | Не путать с | Различие |
| --- | --- | --- |
| Пользователь | Клиент | «Пользователь» — человек, который работает с продуктом. «Клиент» — роль (заказчик) или компонент (клиентское приложение, сторона клиент-сервер). Не заменяйте одно другим. |
| Репозиторий | Хранилище, реестр | «Репозиторий» — версионируемое хранилище кода и истории. «Хранилище» — общее хранилище данных: объектное, файловое, база данных. «Реестр» — каталог образов или пакетов. |
| Логин | Имя пользователя | «Логин» — идентификатор для входа. «Имя пользователя» — отображаемое имя. Если продукт различает понятия, различайте и вы. В прозе — по глоссарию, в шагах — по метке интерфейса. |
| Авторизация | Аутентификация | Аутентификация проверяет личность. Авторизация проверяет права. «Вход» — действие пользователя. В интерфейсе «Авторизация» может означать вход; в шагах следуйте метке. |
| Пароль | Токен, ключ доступа, секрет | Пароль знает пользователь. Токен выдаёт система. Ключ доступа — учётные данные для программы или сервиса. «Секрет» — общее слово для всех трёх; называйте конкретный тип. |
| Удалить | Очистить | «Удалить» — объект. «Очистить» — содержимое. Правило не универсально: «Очистить корзину» удаляет объекты, «Удалить формат» очищает форматирование. Следуйте интерфейсу. |
| Ошибка | Сбой, дефект, баг | «Ошибка» — для пользователя. «Сбой» — отказ сервиса. «Дефект» — ошибка в продукте. «Баг» — внутренний термин. |
| Функция | Возможность | «Функция» — код, API, математика. «Возможность» — то, что умеет продукт. В пользовательских текстах «возможность» часто точнее. |
| Интерфейс | UI | «Интерфейс» — общее понятие: пользовательский, программный, аппаратный. «UI» — пользовательский интерфейс. Если контекст неясен, пишите «пользовательский интерфейс». |
| Каталог | Папка | В GUI — по метке интерфейса. В CLI — «каталог». В одном тексте — один термин. |
| Аккаунт | Учётная запись, профиль | «Аккаунт» — учётная запись и доступ. «Профиль» — данные и настройки. «Учётная запись» — официальный термин. Выбор — по глоссарию. |
| Загрузить | Скачать, выгрузить | «Загрузить» — на сервер (upload). «Скачать» — с сервера (download). «Выгрузить» — экспортировать (export). Если контекст неясен, уточняйте: «загрузить на сервер». |
| Настройка | Параметр, опция | «Настройка» — значение или действие. «Параметр» — именованный вход. «Опция» — выбор. В интерфейсе — по метке. |
| Версия | Релиз, сборка | «Версия» — номер. «Релиз» — выпуск. «Сборка» — артефакт. В примечаниях к выпуску используйте все три точно. |
| Эндпоинт | Конечная точка | «Эндпоинт» — термин API. «Конечная точка» — калька. В API-справке — по глоссарию; в пользовательских текстах — «метод API» или «адрес API». |

## Названия и код

- Пишите названия продуктов точно: GitHub, Git, Docker, Kubernetes, PostgreSQL. Не транслитерируйте: не «ГитХаб», не «Докер».
- Не меняйте написание названий: «в Docker», «на GitHub», «с Kubernetes». Не добавляйте русские окончания.
- Род названий и краткие формы (Postgres, K8s) — по глоссарию. Если род не задан, перестраивайте фразу: «Вышла новая версия PostgreSQL».
- Сохраняйте написание кода: `user_id`, `Content-Type`, `GET`. Не переводите имена параметров, методов, классов, полей, констант и значений перечислений.
- В прозе называйте сущность словом, а идентификатор приводите в моноширинном: «Параметр `user_id` задаёт идентификатор пользователя».
- Не переводите значения, которые обрабатывает программа: статусы, коды, значения перечислений.

## Аббревиатуры

- Расшифровывайте аббревиатуру при первом упоминании в разделе, если аудитория может её не знать.
- API, SDK, CLI и URL не расшифровывайте. UI — только в составных терминах.
- Русские аббревиатуры (БД, ПО, ОС) расшифровывайте, если аудитория не техническая; иначе — по глоссарию.
- Аббревиатуры латиницей не склоняйте: «в API», «с SDK». Не добавляйте русские окончания.
- Составные термины пишите через дефис: SDK-клиент, CLI-команда, URL-адрес, HTML-страница.
- Пишите «ключ API», если глоссарий или интерфейс не требуют «API-ключ».

## Оформление

- Метки интерфейса — **жирным**, точно как в интерфейсе: **Сохранить**, **Папка**.
- Термины как слова — в «кавычках»: «пользователь», «клиент».
- Код, команды, пути и значения — `моноширинным`: `user_id`, `GET`, `/etc/hosts`.
- Точку ставьте после закрывающей разметки: Нажмите **Сохранить**. Введите `user_id`.
- Не используйте кавычки для меток интерфейса.

## Настройка под продукт

1. Замените продуктовые строки в таблицах, универсальные правила оставьте.
2. Заполните `glossary-template.md` и положите его рядом с глоссарием продукта.
3. Добавьте термины из интерфейса и API. Для каждого термина укажите метку интерфейса, имя в API и запрещённые синонимы.
4. Проверьте, что термины совпадают с именами параметров и методов в API, а метки — с интерфейсом.
5. Назначьте владельца и статус: активный, устаревший, предложенный.
6. Обновите переводы и поисковый индекс.

## Проверка

- Найдите запрещённые синонимы: «юзер», «кликнуть», «репа», «деплой», «конфиг», «апдейт», «фича», «баг».
- Проверьте, что одно понятие названо одним термином.
- Проверьте, что UI-метки оформлены жирным, а код — моноширинным.
- Проверьте, что аббревиатуры расшифрованы или входят в исключения.
- Проверьте род, число и падежи по `localization.md`.
- Пройдите `checklist.md`.
