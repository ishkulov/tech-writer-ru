# Проверка терминов

Быстрая проверка для пользовательской документации. Правила — в `terminology.md`, полный чек-лист — в `checklist.md`.

## Запрещённые синонимы

| Искать | Заменить | Где допустимо |
| --- | --- | --- |
| юзер | пользователь | внутренняя переписка |
| кликнуть | нажать | внутренняя переписка |
| репа | репозиторий | внутренняя документация |
| деплой | развёртывание | внутренняя документация, метка интерфейса |
| конфиг | конфигурация | внутренняя документация, метка интерфейса |
| апдейт | обновление | внутренняя документация, метка интерфейса |
| фича | функция, возможность | внутренняя документация |
| баг | дефект, ошибка | внутренняя документация |

## Регулярные выражения

```text
\bюзер\w*
\bклик\w*
\bреп[аы]\b
\bдеплой\w*
\bзадепло\w*
\bконфиг\w*
\bапдейт\w*
\bфич\w*
\bбаг\w*
```

## Как проверять

1. Найдите запрещённые синонимы регулярками.
2. Проверьте каждое совпадение: возможно, это цитата, метка интерфейса или внутренний текст.
3. Замените синоним термином из глоссария.
4. Проверьте, что замена не изменила смысл.
5. Пройдите `checklist.md`.

## Vale и LanguageTool

- **Vale:** добавьте правило `substitution` с парами «запрещённый синоним → термин».
- **LanguageTool:** добавьте пользовательские правила для запрещённых слов.
- Если инструменты не настроены, пройдите таблицу вручную.

Пример правила Vale:

```yaml
extends: substitution
message: "Используйте «%s» вместо «%s»."
level: error
ignorecase: true
swap:
  юзер: пользователь
  кликнуть: нажать
  репа: репозиторий
  деплой: развёртывание
  конфиг: конфигурация
  апдейт: обновление
  фича: функция
  баг: дефект
```

## Тестовые примеры

Плохо: Юзер кликнул по кнопке и получил ошибку.
Хорошо: Пользователь нажал **Сохранить**. Появилась ошибка.

Плохо: Задеплоили конфиг в прод.
Хорошо: Развернули конфигурацию в рабочей среде.

Плохо: Пофиксили баг с логином.
Хорошо: Исправили ошибку входа.
